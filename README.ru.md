# NFixer

[English](README.md) | **Русский**

<img src="nfixer.png" width="96" align="right" alt="">

Чинит и сжимает игровые записи NVIDIA Instant Replay (ShadowPlay):

- находит клипы, у которых начало испорчено переполнением буфера Instant Replay, и отрезает испорченную часть;
- сжимает записи из H.264 в HEVC без видимой потери качества, проверяя результат метрикой VMAF.

Только Windows. Нужны Python 3.9+ и [FFmpeg](https://ffmpeg.org/) с libvmaf (`ffmpeg.exe` и `ffprobe.exe`).
FFmpeg ищется в папке `ffmpeg` рядом с программой, затем в `PATH`; другое место задаётся параметром
`--ffmpeg ПАПКА` или переменной окружения `NFIXER_FFMPEG`. Для сжатия по умолчанию нужна видеокарта NVIDIA
с кодировщиком HEVC; без неё используйте `--encoder x265`.

## Окно приложения

Двойной щелчок по `NFixer.pyw`. Видео `.mp4` и папки добавляются кнопками или перетаскиванием из Проводника
в окно (можно несколько сразу, можно бросить их на сам файл `NFixer.pyw` или его ярлык). Дальше выбираются
действие (проверить / оценить экономию / сжать / обрезать испорченное начало), место для результата и качество.
Есть «Старт», «Стоп», прогресс и журнал. Язык окна (English / Русский) переключается в правом верхнем углу; по умолчанию - английский.

«Стоп» прерывает работу сразу: недописанный файл удаляется, оригинал остаётся, следующий «Старт» продолжит
с того же места. Не запускайте две копии на одних и тех же папках одновременно.

## Командная строка

```
nfixer check    ПУТИ... [--days N]          найти повреждённые записи (только чтение)
nfixer estimate ПУТИ... [--files 12]        прогноз экономии на случайной выборке (только чтение)
nfixer compress ПУТИ... --out ПАПКА         сжать, оригиналы не трогать
nfixer compress ПУТИ... --replace           сжать и заменить оригиналы (после проверки каждого файла)
nfixer repair   ПУТИ... --out ПАПКА         отрезать испорченное начало без перекодирования
```

`ПУТИ` - любое число папок и файлов `.mp4`; длинный список можно передать файлом: `--list список.txt`.
Полезные параметры: `--days N` (только свежие файлы), `--match СТРОКА` (фильтр по пути), `--limit N`,
`--max-hours N`, `--vmaf N`, `--dry-run`. Сообщения по умолчанию на английском; `--lang ru` (перед командой) или переменная `NFIXER_LANG=ru` включают русский. Работу можно прервать Ctrl+C и запустить снова - она продолжится
с места остановки.

Пример: проверить записи за последние сутки.

```
nfixer check "D:\Videos" --days 1
```

## Как сохраняется качество

Сжать уже сжатое видео совсем без потерь нельзя (файл получится больше исходного), поэтому цель -
**визуально неотличимый** результат, и она проверяется измерением, а не на глаз:

1. Из каждого ролика берутся пробные отрезки, кодируются с разной степенью сжатия и сравниваются с оригиналом
   метрикой VMAF. Выбирается самое сильное сжатие, при котором средний VMAF >= 95 и нет провалов на отдельных
   кадрах (5-й перцентиль >= 91). Планка меняется параметром `--vmaf`.
2. Если ролик нельзя уменьшить хотя бы на 15% без потери качества, он остаётся как есть.
3. После кодирования проверяется: то же число кадров и длительность, те же звуковые дорожки (звук копируется
   без перекодирования, названия дорожек сохраняются), не было ошибок чтения исходника, контрольный замер VMAF
   на готовом файле в другом месте ролика. Только после этого (с `--replace`) оригинал заменяется.
4. Разрешение, частота кадров, метки времени каждого кадра, цветовые метки и даты файла сохраняются.

Результат - HEVC (H.265, 8 бит) в MP4. `--encoder x265` сжимает на 10-20% сильнее, но примерно в 5 раз
медленнее. `--encoder av1` ещё компактнее, но старые версии видеоредакторов AV1 не открывают.

Чего ждать (замеры на коротких отрывках, кодировщик NVENC, VMAF около 96-98):

| Записи                             | Экономия    |
|------------------------------------|-------------|
| 1080p, 40-50 Мбит/с                | в ~8 раз    |
| 1440p, 30-40 Мбит/с                | в ~4 раза   |
| 1440p, ~20 Мбит/с                  | 15-25%      |

Записи 1440p на 20 Мбит/с уже сильно сжаты при записи, поэтому запас у них небольшой.
С `--vmaf 93` они уменьшаются на 35-45% ценой едва заметного смягчения мелких деталей.

## Почему ломаются записи Instant Replay

Instant Replay хранит последние N секунд в кольцевом буфере-файле. Его размер NVIDIA App считает как
`длительность x битрейт x 1,2` (например, 270 с x 20 Мбит/с -> 810 МБ), но кодировщику разрешает пиковый
битрейт вдвое выше заданного (до 40 Мбит/с). В динамичных играх реальный битрейт подолгу держится у пика,
буфер заполняется раньше, чем проходит заданное время, и новые кадры затирают самые старые. В сохранённом
клипе индекс по-прежнему указывает на старые кадры, а на их месте лежат чужие данные - отсюда «каша»
в начале ролика. Последняя часть клипа, помещающаяся в буфер, всегда цела.

Обе цифры видны в логе `%ProgramData%\NVIDIA Corporation\ShadowPlay\CaptureCore.log`
(строки `GetVideoTempFileLimit` и `InitEncoderParams`). Поведение наблюдалось в NVIDIA App 11.0.8 и 11.0.9.

Как обойти:

- Гарантированно целой остаётся `длительность повтора x 0,6`. Чтобы всегда получать целые 4,5 минуты,
  ставьте длительность 7,5 минуты; испорченное начало потом снимается действием «Обрезать» (`repair`).
- Либо сохранять повтор чаще.
- После игровой сессии проверять свежие клипы действием «Проверить» (`check --days 1`).

## Как NFixer находит границу повреждения

В MP4 есть индекс: где лежит каждый кадр и сколько занимает. У испорченного клипа индекс верный, но по адресам
первых кадров лежат чужие данные. Настоящий кадр H.264 начинается с заголовка известного вида, поэтому NFixer
читает начало каждого ключевого кадра и находит последний, который на заголовок не похож. Обрезка идёт по
следующему за ним ключевому кадру, у которого целой оказалась вся группа кадров. После обрезки результат
проверяется покадрово и полным декодированием.

## Прочее

- Журнал обработанных файлов и настройки окна лежат в папке `logs` рядом с программой.
- Иконка рисуется скриптом `tools/make_icon.py` (нужен Pillow).
- NFixer не связан с NVIDIA. NVIDIA, ShadowPlay и Instant Replay - товарные знаки их владельца.
